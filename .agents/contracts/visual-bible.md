# Visual bible contract

## States

A bible is `minimal-provisional`, `current-provisional`, or `locked`. State and
version must be explicit; uncertainty must not be laundered into canon.

## Required shape

Record evidence basis, asset purpose, narrative/function role, visual style,
palette, materials/environment language, anatomy/layout/location system,
text/signage posture, belongs/does-not-belong rules, allowed variation, hard
do/don't rules, prompt constraints, evaluation gates, and reference notes.

## Creation and update

Start from repo truth plus inspected, selected, or explicitly approved visual evidence.
Create the smallest bible needed before generation. Update it from accepted
overview/member learning; failures add anti-pattern guidance only when durable,
repeated, or semantically important. Lock only when the family is coherent.

## Interpretation packet

For a specific lane, extract source/version, identity-critical features,
allowed variation, positive constraints, hard negatives, physical/text rules,
continuity constraints, evaluation gates, repair constraints, and explicitly labelled
extrapolation. Interpretation does not create new canon.

## Repair and fresh starts

Repair packets name the failed hard gate, source canon block, passed features
to preserve, required change, and whether editing remains viable. Structural
lane/style/contamination failures or two repeated repair failures require a
fresh generation from the current bible and accepted references.

## Boundaries

Unreviewed candidates, source zips, and session notes are not canon evidence by
default. Do not merge bible creation, interpretation, generation, and image
acceptance into one authority.
