# Image sidecar provenance and path-refresh design

## Problem

The `adventures.visual_sidecar.adjacent.v1` image sidecars that sit next to the project images are the canonical textual representation of each image. Right now they do not record how the image was generated, and several sidecars still carry `repo_image_path` and `repo_sidecar_path` values from the pre-restructure tree (`fairytales/...` and `assets/in-flight/...`).

## Goal

Add a small `image.provenance` block to the sidecar contract, backfill all existing sidecars with the historical generation record, refresh stale paths to the current four-layer tree, and add a lightweight repo-standards check so future sidecars cannot drift.

## Non-goals

- Moving `docs/project/provenance-assets.md` to `.agents/docs/`; that is out of scope.
- Creating a new adventure, visual bible, or deck; this is a repo-shape contract task.
- Hand-editing marketplace-derived skills or `.agents/plugins/`.

## Schema contract

The sidecar `image` object gains a `provenance` child. See `.agents/contracts/image-sidecar-provenance.schema.json` for the machine-readable contract.

Known prompt:

```json
{
  "generator": "ChatGPT / OpenAI image generation",
  "model": "gpt-image-2",
  "generated_at": "2026-08-14T06:58:19Z",
  "prompt_language": "en",
  "prompt": "the exact prompt, if known",
  "prompt_retained": true
}
```

Lost prompt:

```json
{
  "generator": "ChatGPT / OpenAI image generation",
  "model": "gpt-image-2",
  "generated_at": "2026-08-14T06:58:19Z",
  "prompt_language": "en",
  "prompt_retained": false,
  "prompt_unretained_note": "Generated by ChatGPT using the OpenAI image gen tool at generation time; the exact prompt was not preserved."
}
```

## Backfill rules

- All 12 existing sidecars get an `image.provenance` block.
- Default `generator`: "ChatGPT / OpenAI image generation".
- Default `model`: "gpt-image-2".
- `generated_at`: use the sidecar's own `created_at` value if present; otherwise use the image file's commit time or leave `null` if unknown.
- `prompt_retained`: `false` for all existing images.
- `prompt_unretained_note`: the standard note above.

## Path refresh

For each sidecar:

- `repo_image_path` and `repo_sidecar_path` are updated to the current four-layer tree:
  - `fairytales/<...>` -> `published/fairytales/<...>`
  - `assets/in-flight/<...>` -> `workbench/<...>`
- The sidecar filename stays `<image_basename>-sidecar.json`.

## Validation

Do not hand-edit the marketplace-derived `repo-standards` skill. Add a repo-owned validator:

- Create `tools/validate_image_sidecars.py`.
- Call it from the `ci` target in `tools/run.py`, after the `repo-standards` surface check and before the final `git diff --check`.

`tools/validate_image_sidecars.py` must check:

- Every `*-sidecar.json` in `build/`, `style/`, `published/`, and `workbench/` has `image.provenance`.
- `repo_image_path` and `repo_sidecar_path` resolve to existing files in the current tree.
- `sha256`, `byte_size`, `dimensions`, and `mime_type` match the actual image bytes.
- The sidecar JSON is valid against `.agents/contracts/image-sidecar-provenance.schema.json`.

## Acceptance criteria

- All 12 existing sidecars are updated with `image.provenance` and refreshed paths.
- New `.agents/contracts/image-sidecar-provenance.schema.json` exists and is valid JSON.
- `py -3 tools/run.py ci --check` passes.
- `tools/validate_image_sidecars.py` rejects a sidecar with missing `image.provenance` or a stale `repo_image_path`.
