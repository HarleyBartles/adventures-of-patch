# Adventures project doctrine

Status: active repository doctrine

This doctrine holds durable project law for Adventures of Patch. It is not a
skill, task recipe, or substitute for the detailed project playbooks.

## Identity

- Patch is the constant project character and visual canon unless Harley
  explicitly excludes him.
- Patch is not an agent, actor, owner, execution lane, or authority boundary.
- Agent infrastructure belongs under `.agents/`; ordinary project work belongs
  in its canonical project, asset, documentation, playbook, or script home.

## Source truth

- The repository, live issue/PR evidence, repo-tracked receipts, asset guides,
  and indexed project sources are authoritative for their respective facts.
- Uploaded zips, chat attachments, scratch files, memory, generated packages,
  and marketplace caches are context or evidence until the repo explicitly
  adopts them.
- Discover assets through the generated mesh. Do not replace current repo truth
  with a hard-coded source-zip name or remembered path.

## Readiness law

- An adventure begins as a seed, not a production-ready deck.
- Production requires a green frame and green asset readiness. The issue must
  be playbook-ready before the end-to-end PPTX pipeline begins.
- A frame must make the lesson physically happen through a bounded world,
  visible anti-pattern and positive pattern, Patch agency as character,
  function mappings, continuity, story progression, and audience action.
- Generated images are candidates until the image-QA contract accepts them in
  the correct lane. Asset sheets and contact sheets are not body-slide art.

## Resource and publication law

- Deterministic preparation, indexing, QA, receipts, and policy work do not
  spend image-generation credits.
- Do not call work green without the required local validation and, for tracked
  mutation, exact branch/remote/PR publication proof.
- Keep local `adventures-*` skill custody distinct from marketplace projections;
  refresh tooling must preserve the local prefix.
