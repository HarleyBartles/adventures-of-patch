# Future Patch Adventures

Working list of Patch adventure frames for presentations about software teams working with agents.

## Adventure candidates

1. Patch and the Map That Lied - agents need current context, not stale authoritative-looking maps.
2. Patch at the Checkpoint of Intent - good work starts with outcome, constraints, and definition of done.
3. Patch and the Helpful Shortcut - speed without validation creates false green.
4. Patch in the Hall of Mirrors - separate evidence from inference.
5. Patch and the Tiny Change That Wasn't - small changes can have broad blast radius.
6. Patch Meets the Test Goblin - QA uses agents to generate suspicion and edge cases.
7. Patch and the Product Fog Machine - product ambiguity must be surfaced before implementation.
8. Patch Carries Too Many Bags - overloaded prompts should be decomposed into stages.
9. Patch and the Permission Maze - agents need explicit authority boundaries.
10. Patch and the Breadcrumb Trail - make agent work reviewable and auditable.
11. Patch in the Duplicate Village - search existing patterns before inventing new ones.
12. Patch and the Red Button Labelled Refactor - refactors need purpose and guardrails.
13. Patch and the Whispering Logs - debugging starts with observation, not theory.
14. Patch and the Spec That Changed Shape - source precedence and recency matter.
15. Patch and the Review Dragon - reviewers need concise risk-focused summaries.
16. Patch and the Golden Demo - demos are not proof.
17. Patch and the Translation Spell - agents can translate across disciplines while preserving facts.
18. Patch and the Infinite Intern - agents are fast collaborators, not owners of judgment.

## Pattern

Each adventure should make an agent-working principle concrete:
Patch receives a tempting but under-specified task, enters a vivid software-system world, hits a failure mode, learns the operating principle, then exits with a reusable team rule.
